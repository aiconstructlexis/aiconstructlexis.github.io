# StableToolBench
**Type:** Measurement instrument  
**Supporting papers:** 6  

## State of the Field

**What it is.** Across papers, the prevailing description treats StableToolBench as a benchmark for evaluating LLM tool invocation or tool use, especially the accuracy of generated function calls. Definitions also describe it as derived from, or evolving from, ToolBench, with a stable API access setup: one paper describes an API caching mechanism, while another mentions a virtual API server and stable evaluation system. The descriptions converge on its scale, reporting 765 solvable tasks or questions organized into six subsets or subtasks, with variation in tool category and instruction complexity from single-tool to multi-tool instructions.

**What it is claimed to measure.** The available relationship evidence uses StableToolBench to measure tool use. Across the reported relationships, it is linked to one behavioral indicator, Tool use, and no constructs. In one reported use, papers measure tool use by comparing the accuracy of function calls on StableToolBench against baselines, so the measurement claims are concentrated on a single behavioral indicator rather than spread across multiple linked constructs.

**Space of uses.** Papers place StableToolBench within broader evaluation suites and in direct baseline comparisons. It is used alongside RestBench-TMDB in one study, and alongside BFCL, GSM8K, and MATH in another, while Benchmarking Agentic Workflow Generation uses it to compare function-call accuracy for ToolLlama and two one-shot baselines. In these descriptions, it appears as one benchmark within broader evaluations and as a setting for head-to-head function-call accuracy comparisons.

**Concerns raised.** The only concern papers explicitly foreground is stability. One paper introduces StableToolBench as "a stable version of the Rapid-API access system derived from ToolBench using an API caching mechanism", and another description highlights a virtual API server and stable evaluation system.
